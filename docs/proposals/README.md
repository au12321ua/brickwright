## 并行开发约定

以下是 P-001 至 P-003 共用的接口约定。三条线可以从同一基线出发，在各自的短期工作树内开发。[推进方式与覆盖承诺](../decisions.md)

| 提供方 | 消费方 | 对接时须能回答的问题 |
| --- | --- | --- |
| P-003 零件目录 | P-001 查询与装配、P-002 案例 | 给定发布版及零件 ID，返回条目身份、可构造性、碰撞体、带局部坐标和轴向的端点、数据来源及缺项原因。已验证的配对注明验证范围。 |
| P-001 装配与执行 | P-002 技法与修复指南 | 给定接口或装配意图，返回候选的两端及适用条件。试装或执行失败返回稳定原因码、阶段、证据和可行的下一步。内外代理共用这些事实。 |
| P-002 知识查询 | 内外代理 | 给定任务描述、零件 ID 或诊断码，可查到条目 ID、适用条件、示例和来源。P-001 即使查不到知识条目，也能报告错误和直接可行的恢复操作。 |

开发前共用一次小型可行性检查。用一对现有铰链走通“查配对 → 试装舱门”，用基线中没有端点标注的 `2651` 走通“查缺项 → 诊断 → 找到修复指南”。接口尚未实现的一段可用约定的返回样例，记录哪些步骤实际运行过。已核对的侧装例和 2026-10 清单计数可直接复用。检查只用于发现会改变三线分工或数据表示的问题。

P-001 可先用现有零件和少量目录样例开发，P-002 可用现有 SDK 和诊断样例撰写案例，P-003 可直接从固定发布数据生成。开发中以 TDD 和仓库 CI 检查验证实现。合流时集中检查正常装配、失败修复和新增部件，并按 P-001 执行新旧代理配对验收。
