# P-004 — 流程放行与记录产物

Status: accepted

## 问题与目标

现在的外部流程是 `init`、编辑、`validate`、`render`、`finalize`。现有记录保存源码、元数据、验证快照、渲染和导出；
缺少可核对的原始要求、图像特征和模块规划。`finalize` 会重验原生碰撞、悬空及记录附加的测试。
悬空判定把接触支撑算作有支撑，放在别的零件上而没有咬合的零件不会被报告。[验证与导出](../design/validation-and-export.md)

本提案实现[总设计](../design/agent-build-flow.md)第 3 至 6 节：启用流程的记录保存特征清单、规划和评审报告，
程序按[放行条件](../design/agent-build-flow.md#4-流程与放行条件)决定能否导出，整版结构检查报告未咬合的组件。
P-005 写入评审内容，P-006 写入模块约定和模块状态，两者都经过本提案的读写和放行规则。

## 方案

### 流程开关

`Config` 增加 `flow` 选项，命令行为 `--flow/--no-flow`，也可由环境变量 `BRICKWRIGHT_FLOW` 设置。
记录创建时把流程版本写入 `Meta.flow`。旧记录读到的值为空，按现有规则验证和导出。

演示的新版附件通过环境变量开启流程，沿用同一版题目、原始条件和评分。独立派发所需的有效指令入口和烟测见 P-005。
附件能否为代理进程提供环境变量，需在首个集成分支上试跑确认。不行时改为在附件的 `BRICKWRIGHT.md` 中要求加 `--flow`。

### 产物与读写

新增 `brickwright.flow` 模块，用 pydantic 定义特征清单、规划和评审报告，字段按总设计[第 5 节](../design/agent-build-flow.md#5-记录中的新产物)。
每份 JSON 带 `schema_version`，写入时校验格式和引用关系，例如特征引用的完成条件必须存在。

| 产物 | 外部命令 | 内置工具 |
| --- | --- | --- |
| 特征清单 `features.json` | `external features <id> [--set FILE]` | `set_features`、`read_features` |
| 规划 `plan.json` | `external plan <id> [--set FILE]` | `set_plan`、`read_plan` |
| 评审报告 `review.json` | `external review <id> --set FILE` | 由驱动写入 |
| 流程状态 | `external status <id>` | 附在 `validate` 和 `finalize` 的结果中 |

不带 `--set` 时打印当前内容和格式说明。格式错误返回诊断，证据给出 JSON 路径、期望值和实际值。

演示附件在创建记录时直接读入题目原件的 `task.json.checks`，保存题号、文件摘要、原始顺序、稳定编号及逐条原文。共享层接收这些只读条件，无需依赖 OMR 的路径。写特征只允许引用条件或补充目标图、视图名、区域、重要度与拟议简化；原始条件不能被覆盖、删除或降级。校验要求每条原始条件至少被一项特征引用，图上新特征可以独立存在。人工验收直接对原件核对。

### 失效规则

每份产物保存自身的 SHA-256。评审开始时生成不可变输入清单与轮次 ID，包括原始条件、题面、特征、目标图、机位、待交付模型、实际渲染及叠加图摘要。有模块时模型身份包含父源码、实际合并清单及其子快照。报告写回须引用原轮次；过期报告留作历史。
`Record.read_meta` 已按源码摘要判定验证是否过期，流程状态沿用同一做法。

- 源码或合并清单改变，使整件结构报告、相关成品图、评审和当前定稿标记过期。
- 特征或参考输入改变，使受影响的渲染、指标与评审过期。旧意见不能绑定到新输入。
- 规划改变时重新检查组件声明和模块约定；接口改动使两端自检及其合并结果过期。无关模块可复用（P-006）。

### 整版结构检查

`build_and_validate` 为同一快照生成两栏结构报告，旧报告读作空值。第一栏用记录的构建对象运行原生及附加检查。第二栏临时导出同一构建的 MPD，在干净进程中用固定 SDK、标准发布目录和原始 MPD 字节重读，不加载记录代码或自定义端点。记录两栏件数、组件、碰撞、悬空、SDK/目录版本与 MPD 摘要。导入跳件、件数不符或几何无法表示时报告检查不完整并阻止放行。每个实例用子模型路径、件号、位姿定位。
BrickLayer 增加两项查询，供报告使用。

- 每个连通组件与其他组件的接触零件对，基于现有支撑边计算。
- 仅靠接触支撑、没有任何连接的零件。

对主体以外的每个组件列出件数、范围、接触件和预期的两端实例。两个检查口径结果不同，保留两栏和差异依据。按以下规则逐个解释断开的接口。[U-09](../decisions.md#u-09--有证据的装饰接口缺项可带限制放行)

| 分类 | 所需证据 | 演示放行规则 |
| --- | --- | --- |
| 有意独立 | 规划事先声明独立物件、用途及实例，实例与组件成员相符，如停在屋旁的小车 | 两栏碰撞与支撑均通过时允许独立；同一物件中意外脱落的部分另查 |
| 具体接口数据缺项 | 预期两端、相对位姿、接触/对齐证据及标准端点/配合/碰撞数据的可复现缺项。列来源版本和 P-001 或 P-007 的复现；仅查到“有端点”或“零候选”还不能归因 | 两栏碰撞和悬空均通过时，允许规划中可简化的装饰接口带限制放行，在交付报告中逐项列出。必需连接（含所有约定模块接口）须实际接合 |
| 原因未明或确实断开 | 无匹配声明、实例位置不符、拟议配合无证据或已知缺项不能解释该处断开 | 阻止导出，指明待核对的两端及下一步查询 |

主体和组件的成员关系取自连接图。包围范围只用于定位，组件中夹带一件无数据的装饰不会改变其他断口的判定。仅靠接触支撑单列提示。

诊断码使用 `structure.unattached_component`、`structure.data_gap_component`、`structure.contact_only_part`，
证据和样例数量遵循 P-001 约定，可用 `brickwright knowledge search` 检索。
P-006 通过本模块注册模块接口检查，结果并入同一报告。

### 放行和状态

启用流程时，`finalize` 核对以下条件并重验即将交付的快照。临时 MPD 可用于结构复读及评审；全部通过后，才将相同摘要的字节发布为正式导出。

1. 特征清单存在、格式有效，每条完成条件都被引用。
2. 规划存在、格式有效。有模块时，所有模块自检有效（P-006）。
3. 两栏结构检查完整并按上表放行，合并清单及必需模块接口有效。
4. 当前快照已有完整的独立评审。区分“评审通过”和“轮数用尽、带遗留项交付”，后者须列出仍需修改的项。派发/读图失败、过期或重复回写均不消耗有效轮数；最后一次评审后更改模型须重新获得有效评审，不能用过期报告交付。

不满足时返回 `flow.<条件>` 诊断，`next_action` 给出下一条可执行的命令。
`external status` 输出同样的判断，以及各产物的存在情况、是否过期和已用的评审轮数。

### 流程说明

[外部代理指引](../../packages/brickwright/EXTERNAL_AGENT_INSTRUCTIONS.md)和内置提示各增加一节流程说明，只在启用流程时输出。
说明按阶段给出要运行的命令和要写的文件。外观评审步骤引用 P-005 的评审说明，分块步骤引用 P-006 的模块说明。
内置驱动按同样顺序推进。启用流程的演示记录显式设两轮，结构通过后才调用评审；配置为零轮不能构成“用尽”。

## 备选与取舍

- **只在提示中要求按阶段推进。** 改动最小，但代理可以跳过特征清单或评审直接导出，事后无法核对。
- **外部编排程序按阶段分别启动代理。** 控制最强，但需要另写一个在 Harbor 任务内运行的调度器，两条入口不能共用。
- **把所有产物写进 `meta.json`。** 文件少，但每次写入都要重写元数据，也不便于代理单独阅读和编辑。

选用记录中的独立文件加 `finalize` 放行，规则只有一份实现，两条入口都受约束。

## 验证

- 测试先行覆盖：六题原件应导入 18 条原文；删掉一条、替换原文或引用缺失均被发现。覆盖产物格式和依赖失效、旧记录兼容；
  每个放行条件单独不满足时 `finalize` 拒绝导出，并给出对应诊断；`external status` 与 `finalize` 判断一致。
- 复读基线小屋，记录内期望 8 组，交付件为 507 件主体、31 件小车和六片单件窗扇。匹配独立小车声明；逐片给出 `60594/60608` 的实际安装位置与零候选证据。有可复核的接口缺项才归入第二类；移走一片或在另一断口旁加入缺数据件仍须拦截。
- 复读基线巴士，记录内自定义轮辋端点移动 2 LDU 后为 1 组，标准目录重读为 1003 件主体加四条单独的 `30699` 轮胎，碰撞、悬空均为零。四条断口须定位到 `56904/30699`；报告能区别自定义与标准端点，并保留标准试装均碰撞的事实。归档复放可用一份明确标为验收输入的规划检验分类，原基线没有流程规划。
- 同一接口的复现改为不同件对或不同位姿时不能沿用缺项放行；真正咬合的两块砖通过，漏件的标准重读和无法解释的断开均阻止导出。
- 用同一份装饰接口缺项复现验证放行边界。规划事先允许简化且两栏碰撞、悬空均通过时，交付成功并能查到该接口的限制；把它列为必需连接、移除局部复现证据，或使任一栏出现碰撞或悬空，均应拒绝交付。
- 用第二版六题的参考解运行结构报告，逐件确认巴士、四季小屋和 Sea Jet 中多余组件的分类。
  对尚未解释的组件保留未知原因和阻断状态；取得接口证据后按 U-09 重新判定。
- 外部 CLI 与内置工具对同一记录返回一致的状态和诊断。
- 按冻结设置完成基线与新版的对照，结果写入评测报告。
