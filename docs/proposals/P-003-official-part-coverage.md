# P-003 — LDraw 2026-10 全量索引与可验证装配覆盖

Status: accepted

## 覆盖承诺与基线

以 **LDraw Official Parts Library 2026-10** 为首个冻结版本。该版官方库中每个顶层 `parts/*.dat` ID 均可查询，结果能解释它在 BrickLayer 中可以做什么、受什么限制。此口径保留别名、移号、印刷件、贴纸和组合件 ID。`parts/s/`、`p/` 和贴图作为几何依赖处理，`unofficial/` 在版本范围之外。LDraw 公告的独立形状和带图案件数采用另一种统计口径。[版本公告](https://forums.ldraw.org/thread-29680.html) · [官方发布目录](https://library.ldraw.org/updates)

在 fork 的 `cfcdbe6` 上，以本地 2026-10 快照顶层文件名去扩展名，与 `partdata.part_ids()` 求交集，再按合并人工覆盖后的连接器记录是否为空分组，得到以下开发基线。发布时同一统计应能从固定输入重新生成。

| 状态 | ID 数 |
| --- | ---: |
| 已进 BrickLayer 目录，有至少一条连接器记录 | 17,317 |
| 已进目录，无连接器记录 | 4,359 |

当前提取规则以描述和可解析的碰撞网格作为准入条件，连接器可缺省。授权来源和数据用途已在包内 NOTICE 列出。当前缺口中有 2,736 条描述以 `Sticker ` 开头。按新增 ID 排序，会把补贴纸放在铰链和轴孔前面。[准入规则](../../packages/bricklayer/src/bricklayer/ldraw/scripts/selection.py) · [数据回退规则](../../packages/bricklayer/src/bricklayer/ldraw/scripts/fallbacks.py) · [数据来源与许可](../../packages/bricklayer/NOTICE)

## 可复现的目录及能力查询

1. 固定官方完整快照的版本、来源和校验摘要，保存输入 ID 清单。同步钉住参与生成的 BrickNet 连接标注、碰撞体和实际使用的补充数据。每次生成给出新增、变更和缺项明细，可离线比较同一发布版的两次结果。
2. 逐 ID 保存名称、条目性质、规范或替代 ID，以及 SDK 可构造性、几何、碰撞体和连接点的各自状态。来源记录到实际文件或供体 ID、坐标变换、署名及覆盖依据。查询端点使用 BrickLayer 零件局部坐标并标明单位，原始 LDraw 坐标和变换留作核对。连接点可以是部分标注。已验证的配合另按“零件对、端点、安装方式、验证范围”记录。
3. 全量查询可按编号和名称使用。生成模型时可按所需能力筛选，优先返回有可用数据的独立零件，并能展开变体、别名和已验证配对。保留现有 `part_exists`、`PartSpec`、`Element` 和 `search_parts` 对建模目录的约定，给仅可查阅的 ID 提供独立查询。读入旧模型时保留其原始 ID 和位姿。
4. 原因必须来自提取或验证记录。例如“仅有视觉几何，未解析到碰撞网格”“有碰撞体，连接端点尚未标注”“此旧编号转到某件”“已验证某一安装位姿，运动范围未验证”。版本内缺数据、版本外 ID、按定义无需此能力、尚未核实分别表达。把原因和依据提供给 P-001，由它组织运行时反馈。

## 实际补件范围

优先采用现有数据和可证明的刚性别名或同形印刷供体。对高价值缺件根据许可明确的几何生成或补作碰撞体，按几何和参考装配标注端点、轴、自由度及必要的插入深度，再用正反例验证。生成碰撞体要保留销孔、槽口和轴孔的空间，能区分正确嵌入与邻近穿透。贴纸的粘贴、软管的变形等能力在当前引擎没有相应模型时，目录明确说明限制。

| 零件对 | 本次验收的动作 |
| --- | --- |
| `2650` + `2651` | 补上钩臂端点，复现官方组合件 `2651c01-f1` 和 `2651c01-f2` 的收回与伸出姿态，以组合件中的相对变换核对位置。 |
| `53923` + `30553` | 将原先缺席的锁定铰链臂纳入建模，检验单指与双指的配合、正确安装与错位干涉。按可证实的齿位记录结果。 |
| `4275b` + `4276b` | 对开合铰链核对转轴，作为 P-001 舱门任务的候选。 |
| `2780` + `3700`，`3705` + `7229` | 分别验证销入圆孔、十字轴入轴孔，包括错误朝向或偏离孔中心的反例。 |
| `22890` + `14418`，`30237` + `30031` | 分别验证球窝调姿、夹杆安装；对有限的活动空间报告实际采样结果。 |
| `11211` + `3024` | 把板接到指定侧面，验证朝向、啮合与无碰撞。 |

前两行是实质扩容目标，其余行把已有数据纳入可查询的配合验证，覆盖代理常用的六类任务。官方组合件仅证明文件记录的姿态；中间位置和其他安装方式各自需要证据。对于资料无法证实的候选配合，保留缺项及原因，单列尚未达成的装配目标。[已有运动测试](../../packages/bricklayer/tests/modeling/test_articulation.py)

## 取舍与并行边界

把全部顶层 ID 直接放进可构造目录会让只具名称的零件进入碰撞和校验路径。保留独立的版本清单和能力筛选，需要多维护一份由固定输入生成的索引，换来逐件解释、稳定的旧调用语义和真实的装配覆盖。按类别或名字推断端点成本低但容易把不同模具混用，自动回退应留下供体证据。

P-003 提供零件事实、按连接类型检索所需的索引和配合验证记录。P-001 负责具体模型里的空闲端点、试装和失败诊断。P-002 引用零件号查询实际能力。三条线用同一批固定样例对接。[并行约定](README.md#并行开发约定)

## 验收

- 构建产物中的 ID 集合与经校验的官方清单双向差集为空。按能力逐项汇总可还原全量分母；抽查别名、移号、印刷件、贴纸、组合件、仅几何及库外 ID 的结果。相同输入两次生成得到相同内容和差异报告。
- 逐行执行上表，给出具体零件、端点、姿态和检查结果。对新增碰撞体同时跑合法配合与相交反例。升级报告分别列出新增可查 ID、新增可构造件和新增可验证配合。
- 用已有记录检查 SDK 构造、搜索、碰撞、导入和 LDraw 导出；对仅可查阅的 ID 验证查询能解释缺项、建模失败能传递同一原因。发布包包含所需索引、许可与来源信息，普通查询无需安装相邻仓库或下载整套几何库。
