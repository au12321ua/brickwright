# P-005 — 对齐渲染与特征评审

Status: draft

## 问题与目标

现有评审由视角匹配代理先找机位，再让评审模型比较参考图和渲染图，返回一段差异描述和“是否完成”。
[视觉评审](../../packages/brickwright/src/brickwright/driver/critique.py) · [视角匹配](../../packages/brickwright/src/brickwright/driver/viewpoint.py)
渲染只有四个标准视角和按方位角、仰角指定的单张图，不能按题目给出的机位渲染。
评审结论不指向具体特征，也不说明依据，代理难以据此修改。

本提案实现[总设计第 7 节](../design/agent-build-flow.md#7-外观评审)：按给定机位对齐渲染，计算与验证器同口径的指标和差异区域，
由独立的评审代理逐项对照特征清单，并把结论写成 P-004 的评审报告。

## 方案

### 按给定机位渲染

`external render <id> --cameras FILE` 读取 `cameras.json`，按每个视图的视点、目标点、上方向、视场角和图像尺寸渲染，
写到记录的 `out/views/<视图名>.png`，背景透明。机位使用 LDraw 坐标，渲染前按 BrickLayer 与 LDraw 的轴向换算。
未给机位时沿用现有视角和视角匹配代理。

渲染沿用 BrickWright 现有的 ldraw2mesh 与 pygfx 流程，光照和颜色表与验证器保持一致。
验证器的渲染脚本只用于对照测试，不复制进包内。

### 指标与差异区域

`external compare <id> --reference-dir DIR` 按视图名配对 `goal-<视图名>.png` 和渲染图，输出：

- 每个视图的轮廓交并比和同色像素占并集比例，口径与验证器一致：前景为 alpha 不低于 128，同色为 RGB 各通道差不超过 16。
- 差异叠加图，分别标出参考图有而模型缺少的区域、模型多出的区域和颜色不符的区域。
- 按面积排序的前若干个差异区域，每个给出视图、类别、像素包围框和面积。
  多出和颜色不符的区域有模型像素，借深度缓冲换算为模型坐标中的包围范围，并列出覆盖该区域的零件实例。
  缺少的区域没有模型深度，只给出图像位置和相邻的模型零件。

结果写入记录，供评审代理和主代理读取。指标只作为线索，不作为放行条件。

### 评审代理

`external review-instructions <id>` 打印本轮评审说明，用法与现有的 `critique-instructions` 相同：
主代理派出一个新的子代理，原样交给它评审提示，并列出要读的文件。

评审代理只读题面、目标图、特征清单、各视图渲染图、指标和差异叠加图，不读 `build.py` 和搭建过程。
它对每项特征给出结论（保留、部分保留、缺失、已按约定简化），写明依据所在的视图和图上位置，并给出修改建议。
必须保留的特征全部为“保留”或“已按约定简化”时，结论为“通过”，否则为“需要修改”。
主代理用 `external review <id> --set FILE` 写入结果，由 P-004 校验格式并绑定当前源码和特征清单。

内置入口由驱动直接调用评审模型，替换现有评审的提示和结果格式，仍可单独配置评审模型。
未写特征清单的记录继续使用现有评审。

### 从评审到修改

评审报告中每个未达成的特征项附相关视图、差异区域和修改建议。流程说明要求主代理先处理必须保留的项，
修改后重新通过结构检查，再申请下一轮评审。评审轮数和是否通过由 P-004 统计。

## 备选与取舍

- **按分数设放行线。** 实现简单，但分数与平台评分同源，容易变成针对指标的优化，也不反映题面强调的特征。
- **由主代理自评。** 不需要子代理，但搭建者倾向于认可自己的成品。
- **沿用“完成或未完成”的评审。** 无需改格式，但给不出可执行的修改方向，也无法逐项统计。

选用固定机位的程序指标给线索，由独立代理按特征清单下结论。

## 验证

- 测试先行覆盖：机位读取和坐标换算；渲染图尺寸和透明背景；指标在构造的掩码上与验证器公式一致；
  差异区域的分类、排序和坐标换算；评审报告的格式校验和“通过”的判定规则；无特征清单时回退到现有评审。
- 对照测试：用第二版六题的参考解按 `cameras.json` 渲染，与目标图比较，每个视图的轮廓交并比和颜色分都应接近 1。
  阈值在首次运行后记录。偏差较大时先排查光照、颜色表和坐标换算，再接入评审。
- 基线的 Codex 已提供子代理工具，但只在明确要求时使用，评审说明须明确要求派出子代理。
  新版首个试次确认子代理能读取图片。不能时，`external review` 增加由 BrickWright 直接调用评审模型的方式，并确认任务环境能访问模型接口。
- 在对照评测中统计每轮评审的特征项数、带图上依据的比例，以及修改后结论从“需要修改”转为“通过”的项数。
