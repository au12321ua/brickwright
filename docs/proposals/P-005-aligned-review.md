# P-005 — 对齐渲染与特征评审

Status: accepted

## 问题与目标

现有评审由视角匹配代理先找机位，再让评审模型比较参考图和渲染图，返回一段差异描述和“是否完成”。
视觉评审（`git show e88513e:packages/brickwright/src/brickwright/driver/critique.py`） · 视角匹配（`git show e88513e:packages/brickwright/src/brickwright/driver/viewpoint.py`）
现有 CLI 提供四个标准视角及按方位角、仰角渲染的单张图。基线六题都尝试过按题目机位自行渲染或对照，有的手调缩放或视场角，有的修改软件光栅器。共享实现需要给出跨题、跨版本可复现的投影与评分。
评审结论不指向具体特征，也不说明依据，代理难以据此修改。

本提案实现[总设计第 7 节](../design/agent-build-flow.md#7-外观评审)：按给定机位对齐渲染，计算与验证器同口径的指标和差异区域，
由独立的评审代理逐项对照特征清单，并把结论写成 P-004 的评审报告。

## 方案

### 按给定机位渲染

`external render <id> --cameras FILE` 读取 `cameras.json`，按每个视图的视点、目标点、上方向、视场角和图像尺寸渲染，
写到记录的 `out/views/<视图名>.png`，背景透明。机位使用 LDraw 坐标，渲染前按 BrickLayer 与 LDraw 的轴向换算。
未给机位时沿用现有视角和视角匹配代理。

渲染沿用 BrickWright 现有的 ldraw2mesh 与 pygfx 流程，固定发布库、颜色表、模型间隙、实例排序、光照和透明背景。按题目像素宽高和垂直视场角设置投影，核对 pygfx 的宽高比与 zoom 换算。
验证器的渲染脚本只用于对照测试，不复制进包内。

### 指标与差异区域

`external compare <id> --reference-dir DIR` 按视图名配对 `goal-<视图名>.png` 和渲染图，输出：

- 每个视图的轮廓交并比和同色像素占并集比例，口径与验证器一致：前景为 alpha 不低于 128，同色为 RGB 各通道差不超过 16。
- 差异叠加图，分别标出参考图有而模型缺少的区域、模型多出的区域和颜色不符的区域。
- 首期按面积排序差异区域，给出视图、类别、像素包围框和面积，供评审标注位置。
- 后续可用深度缓冲和实例映射定位多出或颜色不符的模型零件；参考独有区域只标二维位置及可确定的相邻零件。首期演示用二维证据即可验收。

结果写入记录，供评审代理和主代理读取。指标只作为线索，不作为放行条件。

### 评审代理

`external review-instructions <id>` 从结构已通过的不可变版本准备本轮输入。派发前保存轮次 ID、模型及模块快照、已渲染视图、特征、原始题面与条件、目标图、机位、指标和叠加图的摘要；评审读取清单指向的只读副本。主代理在运行环境认可的用户指令或适用的代理指引中获明确派发授权，每轮开启无搭建历史的新会话。基线中五题成功打印过要求派发的说明，实际均未派发，烟测须能观察到独立会话的执行和返回。

评审代理只读题面、目标图、特征清单、各视图渲染图、指标和差异叠加图，不读 `build.py` 和搭建过程。
它先对原始完成条件逐条核对，再对清单给出保留、部分保留、缺失或已按约定简化的结论。发现遗漏时可新增发现，引用原条件或目标图中的视图和框选位置，说明对成品的影响及可执行的修改建议。原文未要求但图片可见的特征注明图像来源。未经约定的简化保留为待处理项。
必须满足的条件及特征都能从证据确认，且无待处理的必需遗漏时才判“通过”。否则判“需要修改”。条件涉及内部连接且图上不可见时，注明视觉证据不足，交由 P-004 的结构证据核实。
主代理用 `external review <id> --set FILE` 交回原轮次结果。P-004 对照派发时的摘要，当前已变更则归档为过期，重复提交幂等。保留每轮的输入、报告与遗留项。失败或失效的评审不计轮数；轮数用尽只能给当前已评版本标记“带遗留项交付”。

内置入口由驱动直接调用评审模型，替换现有评审的提示和结果格式，仍可单独配置评审模型。
未写特征清单的记录继续使用现有评审。

### 从评审到修改

评审报告中每个未达成的特征项附相关视图、差异区域和修改建议。流程说明要求主代理先处理必须保留的项，
修改后重新通过结构检查，再申请下一轮评审。评审轮数和是否通过由 P-004 统计。

## 备选与取舍

- **按分数设放行线。** 实现简单，但分数与平台评分同源，容易变成针对指标的优化，也不反映题面强调的特征。
- **由主代理自评。** 不需要子代理，但搭建者倾向于认可自己的成品。
- **沿用“完成或未完成”的评审。** 无需改格式，但给不出可执行的修改方向，也无法逐项统计。

选用固定机位的程序指标给线索，由独立代理按特征清单下结论。

## 验证

1. **校准优先。** 锁定评测渲染环境和目标图。在归档的 30 对 PNG 上复算两项指标，逐项与 `score-details.json` 相差至多 `1e-12`。随后以相同机位重渲染全部六份参考解和六份基线 MPD。建议参考解各视图两项指标均 ≥ 0.995，基线各视图与归档的绝对差均 ≤ 0.005。阈值在正式对照前冻结；超差先定位投影、排序、光照或几何差异，保留失败视图。测试覆盖掩码边界、反向/俯视、透明度及二维差异框。
2. **独立读图。** 首次试跑保留父子会话 ID、模型与强度、图片输入/读取记录和有效回执。用一对有局部差异的图隐去部位文字提示，要求评审指对视图和区域；刻意漏列一个可见特征，要求它独立补报。无派发、无法读图或位置不符均未通过。备用独立评审模型调用记录实际路径，仍须按 U-07 配置和通过相同读图检查。模拟评审期间替换模型、特征或参考图，旧报告均不能给新版本放行。
3. **喷气机返修演示。** 以归档喷气机及其五张目标图建立可重复的起点（757/770 件，端视轮廓 0.640、颜色分 0.150）。盲评输入不提示偏差答案。评审须定位一个可见偏差，例如端视机腹或进气口截面，并用侧视或另一机位交叉说明；“双尾翼没有外倾”与成品不符。主代理据此在预算内修改，标准目录重读仍通过结构检查。下一轮以相同机位复评，保存原区域在修改前后的叠图与局部数值，并由人工在隐藏版本的同机位对照中确认该处更接近目标。只提高总分、只换评语或两轮耗尽均不能代替这次改善。
4. **记录与兼容。** 检查每条原始条件的结论、带位置依据的项数、遗漏与修正数、各轮有效性和最终交付状态。轮次用尽且最新有效报告仍要求修改时只计为带遗留项交付。验证旧流程和未启用特征清单的记录沿用原评审。

喷气机的同机位盲评用于判定局部改善。六题正式对照分别比较整组的交付通过率、平台分均值和原始完成条件满足数，三项均须达到或超过基线；各题的涨跌保留在报告中。[U-10](../decisions.md#u-10--六题整体不退步并展示局部改善)
