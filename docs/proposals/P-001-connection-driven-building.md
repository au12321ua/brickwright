# P-001 — 按连接关系选件、装配与修复

Status: accepted

## 问题与目标

代理接到“做一扇向上打开的舱门”时，需要找到配套的两半铰链、决定轴向、把门板装到舱体上，再留出开启空间。当前 `search_parts` 主要按文字和零件属性找件，`find_connector` 和 `connect` 从已经选好的零件出发。中间的选件和配对工作落在代理身上。已有按凸点网格搭墙、铺板和填充的便捷路径，也已有侧装和球窝的直接装配示例。[搜索实现](../../packages/bricklayer/src/bricklayer/parts/search.py) · [连接示例](../../packages/bricklayer/src/bricklayer/geometry/connections.py)

上游 issue #4 报告，同模型在 300 个 BrickBench 任务上，BrickWright 通过连接器放置的零件占 4.6%，BrickAgent 为 51.8%。对 719 次失败碰撞检查的复查中，换用新碰撞体会使 13 次通过。这是特定版本和任务集上的观察。我们要检验的假设是，降低选配和修复成本，会让代理在请求确实需要侧装、偏轴或活动连接时主动采用这些结构。[上游讨论与评测](https://github.com/AvaLovelace1/brickwright/issues/4)

## 从意图到可验证的装配

1. **发现。** 支持从装配意图（侧挂、转动、滑动、夹持、球头调姿）查询配对组合，也支持从已放置零件或子模型的可用端点反查配对件。按运动要求、端点相容性、零件能力和常用程度筛选。目录和端点来自 P-003，配合与自由度由 BrickLayer 的现有规则判定。
2. **选择。** 候选给出两端零件和端点、方向、安装位姿及匹配理由。只知道两类接口可配时，标明还需在当前模型上试装。有多个孔或安装方向时，允许按面、方位、邻近点和开启方向缩小范围。对可沿杆或轴滑动的连接，按有效行程检查还能使用的区段。
3. **装配。** 在修改模型前用已有的配合求解、碰撞和运动检查试装少量候选。对等价候选用稳定顺序，给出哪些候选做过哪些检查。选定后复用 `LegoBuild.connect`、`Mounting`、`MotionRange`。如果查询后模型发生变化，提交装配时复查关键条件。失败的候选不留下零件或关节。
4. **代理入口。** 内置工具和外部代理可调用同一组 Python 查询与装配操作。两者的搭建指南都从任务意图给出入口。网格铺砌、普通层叠和填充继续用现有工具，活动部件、转角和子模型接口则有可发现的连接路径。查询候选和试装均可独立调用。

## 执行错误是代理接口的一部分

目前验证报告已有 `error_type`、traceback、源码摘要和逐项检查，碰撞详情能列出零件，运动检查能指出部分失败姿态。探索分别捕获加载模型和执行片段的异常。内置 `finalize` 传给模型的文本可能只剩失败检查名，外部 CLI 却会输出嵌套报告。由最先掌握事实的一层生成诊断，沿两条入口传递，避免在显示端用字符串猜原因。[验证与快照](../design/validation-and-export.md) · [内置工具结果](../../packages/brickwright/src/brickwright/tools/registry.py) · [外部 CLI](../../packages/brickwright/src/brickwright/cli.py)

每条诊断约定稳定的 `code`、失败阶段 `stage`、简短说明 `message`、结构化证据 `evidence` 和有依据时的 `next_action`。下一步应能在当前入口执行。证据可含工具参数名、源码快照中的文件与行号、子模型实例路径、零件 ID、两个端点、期望值和实际值、发生干涉的采样姿态。下面是拟议输出的一条诊断，实例名与行号仅用于说明。

```json
{
  "stage": "create_build",
  "code": "connector.ambiguous",
  "message": "boom 的两个销孔都符合本次选择。",
  "evidence": {
    "source": {"file": "build.py", "line": 18},
    "placement": "boom", "part_id": "32000", "type": "pin_hole", "matches": 2
  },
  "next_action": "用 boom.find_connectors('pin_hole') 查看两个孔的位置，再用 toward 选择靠近安装点的孔。"
}
```

| 失败阶段 | 代理应该收到的事实和可执行反馈 |
| --- | --- |
| 工具调用、编辑、探索 | 区分工具名有误、参数 JSON 损坏、字段缺失和取值超界。编辑冲突沿用最近匹配、行号和原子批量编辑结果。片段异常定位到片段，加载已保存模型失败定位到对应的 `build.py`。 |
| 加载、执行搭建或自测代码 | 区分语法、导入、构建和自测异常。优先展示最相关的用户源码位置、异常类型和原始消息，保留详细栈供追查。对未识别异常返回已知事实。 |
| 选件与配合 | 区分版本中无此 ID、官方件缺数据、端点歧义、类型不配、占用或姿态无解。可选端点和替代件来自实际查询，缺的是目录数据时可以直接查缺项。 |
| 静态和运动验证 | 悬空报告定位实例，连通性报告给出相关组件，碰撞给出零件对。运动干涉或脱开给出关节、采样位置和涉及实例。建议调整有证据指向的安装方向、位置或净空。 |
| 子进程、渲染、导出 | 超时给出操作和限时，异常退出给出可得的退出码，缺库给出环境修复办法。区分模型校验失败和通过校验后的输出失败。遇到 `SourceChanged` 指向重新验证当前源码。 |

例如，门板和门框在 45° 处发生碰撞时，调用 `finalize` 的代理在本次结果里就能读到这两个实例、关节和失败角度，继而检查铰链安装面。构建过程中出现语法错误时，后续的碰撞和运动检查尚未执行，报告只展示已发生的错误。可以直接重试、必须修改源码、需要补数据或修复环境，分别依据当前证据给出建议。

对大量同类问题返回总数、有限个可定位的样例及详细报告位置。源码位置绑定实际执行的快照，执行器拿不到的行号或零件路径允许缺省。在现有报告上增添可选诊断，旧记录仍能读取，现有字段、检查语义、CLI 退出码、源码失效和导出清理按当前约定工作。内置代理的工具消息也应带上修复所需的数据。

## 取舍与并行边界

只改提示词成本低，却要求代理自行枚举零件和端点。全库枚举所有配对及位姿则会放大搜索开销，也无法预知目标模型的遮挡。选用按接口检索、按当前模型限量试装，使匹配规则、碰撞体和关节求解各有一个权威实现。SDK 原有放置方法仍可单独使用。

本提案负责装配求解、运行时诊断格式及工具和 CLI 的传递。P-003 提供静态零件事实及缺项原因，P-002 用诊断码关联修复指南。三条线用索引页约定的样例并行工作。[并行约定](README.md#并行开发约定)

## 验收

- 对侧装面板、铰接舱门、销轴连接、球窝调姿、普通砖墙使用固定任务描述、部件或库存约束和结果断言。侧板应实际啮合；舱门沿指定轴从关闭到 60° 的约定采样位姿应无碰撞且保持连接；普通砖墙应能继续网格搭建。
- 通过正常入口注入语法错误、歧义端点、目录缺项、运动干涉、超时和导出失败。内置工具与对应外部命令返回一致的阶段、原因和证据。按反馈修正一个端点选择后，重新验证和导出成功。失败报告与旧源码快照仍可追溯。
- 用自动化用例覆盖候选试装后状态一致、旧报告读取、校验失败禁止正式导出。
- **新旧代理配对验收。** 提前固定同一批自然语言搭建任务、模型版本、推理设置、预算、运行次数和评分规则。题目只描述成品和所需功能，不提示使用连接、某个接口或某种放置方法。两版分别用自己的原生代理指引。对成品中实际按配合关系定位的零件实例计数，覆盖重复子模型并去重；普通坐标放置后偶然啮合、失败试装及最终移除的零件不计入分子。记录逐题分子和成品零件总数，汇总整批比例。固定任务全部纳入完成度统计，缺失成品记为未完成。
- 验收同时满足三项：新版整批的连接放置比例严格提高，按相同量表评定的整体成品质量和任务完成度均达到或超过旧版。质量评价包含结构有效性、外观和要求的功能，成品评阅隐藏版本身份。保留两版产物、实际用量和逐题评分，任一项缺少真实对照数据则标记待验收。[U-05](../decisions.md#u-05--连接放置的配对验收)

## 实现与待验收项

SDK 与代理指引已接入配对查询、模型内候选、试装和提交。诊断贯通内置工具与外部 CLI，可按原因码查询知识库。两孔零件的回归用例从验证失败开始，定位到具体零件与歧义端点，通过指南修正后重新导出。[装配 SDK](../../packages/bricklayer/src/bricklayer/modeling/assembly.py) · [执行诊断](../design/validation-and-export.md#代理收到的诊断) · [修复回归](../../packages/brickwright/tests/tools/test_connection_repair.py)

原生代理的五道任务、统一预算、成品来源计量和盲评工具已完成离线回归。Maestro 外部代理首轮成品质量和完成度持平，连接放置占比从 20.6% 降到 16.8%。P-001 保持 `accepted`。[配对协议与外部实验](../design/p001-paired-evaluation.md#maestro-外部代理对照)
