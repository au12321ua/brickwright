# P-006 — 模块接口与分块搭建

Status: accepted

## 问题与目标

现有的 `dispatch_subagents` 让子代理在各自的临时记录中工作，只把文本交回主代理，由主代理自己整合代码。
子代理派发（`git show e88513e:packages/brickwright/src/brickwright/tools/subagents.py`）
子代理不知道自己负责的范围和接口，主代理也无法检查交回的部件能否接上。外部入口没有对应的分块方式。

本提案实现[总设计第 8 节](../design/agent-build-flow.md#8-模块化搭建)：模块约定写在 P-004 的规划中，
每个模块在自己的子记录里搭建和自检，父记录按约定合并，合并后检查跨模块的接口。
演示用伦敦双层巴士 R-10258。基线已会分解代码，巴士的底盘、楼梯、两层车身、车顶各有构建函数，喷气机甚至导出七个子模型。本提案用独立代理交回的模块、可复核的接口和局部返工检验分块能力。

## 方案

### 模块约定

规划用整体 LDraw 坐标及 LDU 声明每个模块的主体占用范围、局部原点与朝向、配色、件数预算及接口。主体范围的内部互不重叠，可共享边界。每个接口另写两端模块和实例角色、连接类型及数量、位置与轴向、允许伸入对方主体的几何区域（截面、方向、最大深度与容差）。例如底盘的销可沿指定轴进入下层车身的孔；相邻装饰板没有该许可。
P-004 写入规划时检查编号唯一、两端归属、接口空间与两端范围相接、尺寸及坐标一致。接口空间只授权指定配合几何越过边界，仍须用标准目录验证端点与碰撞。

每个模块的约定摘要覆盖自己的主体、坐标、预算、共用配色及相关接口。同一接口变动会改变两端摘要。其他模块的有效快照可复用。

### 模块记录

`external module init <父记录> <模块编号>` 在父记录的 `modules/<模块编号>/` 下创建子记录。
子记录包含该模块的约定摘要、局部坐标系和共用颜色。生成的 `build.py` 模板返回局部坐标中的 `LegoBuild`，
并在注释中列出接口在局部坐标中的位置和方向。

模块用普通的 `external validate` 和 `finalize` 验证，额外检查：

- 将局部实例变换到整体坐标，检查越过主体边界的几何是否全部属于声明的配合件及接口空间。越界报告实例、接口、方向和超出量；整件包围框只能筛出待查实例。
- 每个接口在声明的位置和方向上有对应类型的空闲连接点，缺失时给出最近的候选连接点及偏差。

诊断码为 `module.outside_occupancy`、`module.interface_missing` 和 `module.contract_stale`。
外部入口另有 `external module status <父记录>`，列出各模块的状态、约定是否过期和用时。

### 合并

父记录的 `build.py` 用 `brickwright.modules.place_module(build, "<模块编号>")` 读取模块，并按约定放置为子模型。
父记录在合并开始时冻结清单，每项含模块 ID、不可变子快照 ID 与源码摘要、自检报告摘要、约定摘要、放置变换。只加载清单指向且验证通过的内容。缺快照、内容与摘要不符或约定失效均中止。验证、渲染和导出使用同一清单及其摘要；整件身份由父源码、清单及生成的 MPD 共同确定。
导出的 MPD 以模块编号命名子模型。

合并后的整版结构检查由 P-004 执行。本模块对照每个约定的实例、端点、世界坐标、类型、方向及数量，在标准目录重读的 MPD 中给出实际配合证据。即使两模块经其他部件连成一体，指定接口未接仍失败。跨模块碰撞和未咬合组件标出所属模块。

### 并行

外部入口提供 `external module instructions <子记录>`，打印模块搭建说明。主代理为每个模块派一个 Codex 子代理，
子代理在授权派发的独立会话中只写自己的子记录，返回会话 ID、子快照及自检结果。记录开始和结束时间，可核对并发和各自产物。

内置入口的 `dispatch_subagents` 任务增加可选的 `module` 字段。指定后子代理在对应子记录上工作，
返回记录编号、自检结果和是否完成，主代理不再需要整合代码文本。

### 返工与耗时

编辑 A 的源码只使 A 的新版本待自检。已封存的整件仍能用原清单复现；状态提示 A 有更新，选用新 A 时必须重做整件合并、结构报告和外观评审，即便父源码字节相同。修改 A–B 接口时两端均须重新自检，无关 C 的摘要不变。正在合并时有新版本，无论成功或重试，同一次导出均只能使用一份完整清单。

## 备选与取舍

- **所有模块写在同一个 `build.py` 的不同函数里。** 无需新记录类型，但并行的代理会同时编辑同一文件，模块也无法单独验证。
- **沿用子代理交回代码文本。** 不改派发接口，但整合由主代理手工完成，接口错误要到合并后才暴露。
- **由程序自动划分模块。** 可以减轻规划负担，但划分依赖对结构的理解，本轮由代理按接口能否先定来划分。

选用子记录加约定摘要：模块可独立验证和并行搭建，失效范围也明确。

## 验证

- 测试先行覆盖旋转后的局部坐标、主体重叠和接口越界。对齐的一对销孔或叠板凸点可伸入声明空间；伸入过深、错孔、少一个接口、无关零件伸入以及真实碰撞均须失败。归档清单须在子记录更新后仍可重建相同 MPD。
- 三模块回归分别只改 A 源码、再改 A–B 接口。断言上述自检失效集合、整件报告和评审失效，C 可复用。测试合并期间子快照变化、错误摘要、未通过自检与导出保留子模型名称。
- 内置派发：指定 `module` 的子代理在正确的子记录上工作，结果包含记录编号和自检状态。
- **能力验收。** 巴士至少由两个不同搭建会话按同一规划独立交回模块，留存会话、时间和快照证据；合并后全部约定接口可逐一复核、结构及交付通过。演示修改一个模块并复用无关模块，验证父记录重新评审了正确版本。
- **效率对照。** 巴士整体组和分块组均开启相同版本的 P-004/P-005，冻结模型与强度、题目、时限、次数、评分、评审上限和环境资源，说明实际并发度。逐组报告交付、原始条件盲评、逐视图和平台分、评审遗留项；报告从开始到交付的墙钟（含规划、派发、等待、合并、返工、复评），主/子/评审代理输入、缓存、输出 token 合计，以及各模块的返工次数和用时。各代理耗时相加不可当作墙钟。只有在预定质量条件成立且分块组端到端更短时才报告提速；耗时持平或更长时仍按前一条独立判定能力。
