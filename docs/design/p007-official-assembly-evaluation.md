## 逐样本检查

直接摆放按相同宿主和子件的两个实例查配合端点及碰撞。查询只给子件和目标旋转，候选上限 20，试装上限 8，按 SDK 返回次序。等价比较使用宿主原始 LDraw 局部坐标，平移误差上限 0.1 LDU，完整旋转角差上限 0.1°。轮组保留轮胎相位和端面方向，铰链保留目标倾角和铰轴。

轮组负例沿轮胎局部横向错位 1 LDU，打破轮辋和胎圈的同轴条件。另加 7039 与 56904 两种座深错位。铰链每例做轴向错位 5 LDU 和铰轴额外倾斜 10° 两项检查。报告分别保存错误位姿下的直接配合、试装提交是否拒绝以及实际落点。提交校正到参考位置单独记为 `corrected_to_reference`。

## 根因和修正

- **7039 轮辋座深。** 源标注的 `fixed_5_in` 在 Z=-2.33335 LDU。组合内 `497a.dat` 的半径 19 LDU 接合圆柱两端是 -8 和 +4，座深中心为 -2。修正应用于 BrickNet 供体，再传给移号件 497，保留其他端点。官方 `7039c01` 和 `7039c02` 是 u9131 的两种颜色，`7039c03` 使用结构不同的 3483。三个文件修前均只在旧错位处通过，修后均在正式预算的第一项恢复官方位置，旧落点被拒绝。
- **56904 轮辋座深。** `s/56904s00.dat` 的半径 38 LDU 保持肩与 56898 的胎圈对应界面以 Z=0 为中心。源标注 `fixed_21_in` 设在 Z=-2 LDU，试装会撞入保持肩。把供体端点移回 Z=0 后，`56904c01` 的 56904/56898 和巴士原 MPD 中的四套 56904/30699 均恢复。应用对照用存档的原始刚体变换，轮组的官方样本计数独立。
- **刚性铰链候选顺序。** 3135c01、3149ec01、3324ec01、73983 的正确配合在扩预算诊断中分别位于第 21、89、221、10 项。与其它卡扣、网格候选竞争导致它们漏过默认试装预算。已知子件和目标旋转时，将轴向与目标相容的铰链候选优先放入预算，保留显式安装选项的优先顺序；上述四例与留出龙颈样本 52258p01c01 均恢复到第 1 项。76442c01 仍有 SDK 几何碰撞，其余原通过样本及 24 个负例维持通过。

每次源标注修正及铰链排序修改后都重跑三组各 117 个实例对、137 个负例。三次差分均没有通过转失败。三次比较分别改变 3、5、5 个样本，其中第三次均为等价恢复。

## 全量筛查

报告有 5,322 个唯一条目。一行对应一个顶层 ID，包含 5,164 个 assembly、152 个移号、5 个别名和 1 个贴纸。98 行执行了所有已识别的适用接口，15 行另有未覆盖的物理子件，5,209 行尚未验证。两项外部几何依赖缺失记录在各自条目中。别名和移号保留原 ID、解析到的 ID 及引用变换。

已具备正例、等价和负例判据的轮组与刚性铰链共执行 113 个官方接口。其余按命名发现的轮组、铰链、轴孔/销、球窝、板件和柔性件保留待专门判定的具体实例，仍需证明配合端和姿态。贴纸归为装饰。同现的物理零件、没有可导入刚体或无接口依据的文件均有各自原因，表中每个待判定或证据不足的观察保留来源实例。复合子件既可整体接受验证，也保留其内部尚未验证的实例。

## 复跑

从任务工作树运行。省去 `--bus-mpd` 时，报告仍包含完整官方样本和清单，巴士应用对照没有输入。

```sh
uv run python -m bricklayer.ldraw.scripts.official_assemblies check \
  --ldraw ../LDraw_标准零件库_20261111/ldraw \
  --bus-mpd /path/to/archived/R-10258/model.mpd \
  --output result.json --inventory inventory.json
uv run python -m bricklayer.ldraw.scripts.official_assemblies diff \
  before.json result.json --output diff.json
```

输出附运行命令、库指纹、SDK 版本、已安装几何和端点数据的文件指纹以及规则版本。工作区的 `.local/agent-build-flow/p007/` 存放修前、每次修正后的逐例结果、差分和 5,322 行清单。
