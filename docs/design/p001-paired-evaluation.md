# P-001 新旧代理配对验收

状态为待验收。本轮交付测量和配对流程，离线测试使用可执行的本地搭建记录。真实模型对照及盲评待运行。见 [P-001 验收](../proposals/P-001-connection-driven-building.md#验收) 和 [U-05](../decisions.md#u-05--连接放置的配对验收)。

## 冻结实验计划

准备两份干净的 Git 工作树，一份固定到 P-001 改动前的基线提交，另一份固定到含 P-001 实现的提交。在两份工作树中分别运行 `uv sync --locked`。控制命令可以从含评测程序的工作树运行。两版生成时共用同一个 LDraw 零件库及提供方配置，评测会核对实际使用的 Python 版本、零件库和模型请求设置，并按版本记录各自的 `uv.lock` 摘要。

以下命令中的目录应使用绝对路径。`P001_MODEL` 指向可用且有价格资料的固定模型版本。例中的轮次和每次预算须在开始调用模型前确定。五题各做一次需要十次搭建运行。美元花费在每次模型响应后核算，最后一次响应的费用可能使单次运行超过设定额度。

```sh
uv run --locked python -m brickwright.evaluation.p001 init "$P001_OUTPUT" \
  --model "$P001_MODEL" --effort medium --repetitions 1 \
  --max-turns 30 --max-validations 12 --max-cost 0.25 \
  --build-timeout 30 --render-timeout 60 --request-timeout 120
```

`private/plan.json` 固定题目、每题要求、量表、模型版本、推理强度、重复次数和预算。五题是侧面指示牌、上掀舱门、旋转轮、可调台灯和普通砖墙。提示给出形态、功能和成品限制，由代理自行选件和搭建。量表独立用于成品评阅。运行只使用每版原生提示词和工具，子代理和外层视觉批评轮次均关闭。

## 生成、盲评和汇总

```sh
uv run --locked python -m brickwright.evaluation.p001 run "$P001_OUTPUT" \
  --old "$P001_BASELINE" --new "$P001_CANDIDATE"
uv run --locked python -m brickwright.evaluation.p001 review "$P001_OUTPUT"
```

在同一命令中提供两份工作树时，程序逐题配对并交替先跑哪一版。也可分别传入 `--old` 和 `--new`，继续使用同一份计划。每个固定试次只生成一次，并保留原生记录、命令结果、逐个响应的实际模型标识和用量。正常耗尽预算或代理停止但未输出成品时，该题按未完成处理。没有模型响应、混用响应版本或用量与费用无法核实的试次仍留在记录中，并使对照处于待验收。遇到这类问题，生成命令保存当次记录后停止批次。中断留下的已启动试次也保留，恢复命令可启动其余未开始的试次。

`review` 重放每个正式产出的源码，核对验证报告、源码摘要和 LDraw 文件，生成可单独交给盲评者的 `review/`。其中 `review.json` 提供随机编号、题目、量表、成品尺寸和结构数据。成品目录提供 `model.ldr`，有预览时附 `preview.png`。涉及已声明运动的模型可附采样结果和极限位姿，评阅者也可由成品几何判断动作能力。原始记录及编号映射留在 `private/`。

评阅者在 `scores.json` 中将每件成品对应的 `null` 替换为包含 `structure`、`appearance`、`function`、`complete` 和 `notes` 的对象。三个分项分别取 0、1 或 2，`complete` 为布尔值，`notes` 记录要求的达成情况及可见证据。缺少成品的试次自动计为未完成。

```sh
uv run --locked python -m brickwright.evaluation.p001 report "$P001_OUTPUT" \
  --scores "$P001_OUTPUT/review/scores.json"
```

`private/report.json` 保存逐题配对、实耗用量、各版总计和验收结果。省略 `--scores` 可查看进度。出现缺失试次、计量或盲评分数时，状态保持 `pending`。

## 连接放置计数

计量器在每版自己的运行环境中执行正式产出的 `build.py`。通过 `LegoBuild.connect` 或 `LegoBuild.place_connection` 成功定位并保留在最终模型中的放置带有来源标记。连接放置一个子模型时，其所有叶子零件都随之定位，每个实例计一次。重复使用同一子模型会重算其中的各个实例，内部也用连接定位的零件在总分子里去重。副本、`extend` 合并、展平、镜像和姿态快照保留来源。以坐标或网格定位后形成的啮合、试装中未提交的零件和最终移除的零件都排除在分子之外。通过 `connect` 使用几何参考点，或原参考件随后被移除时，只要放置的实例仍保留，就有连接放置来源。

结果另列直接通过连接定位的单件、随连接放置子模型移动的叶子、以及最终模型中仍有已记录关节的子端点叶子。前两个计数可能重叠，关节子端点数用于核对。每版的主指标用所有成品的连接放置叶子总数除以成品叶子总数。

- 连接放置比例严格提高。
- 每版成品的平均盲评总分保持或提高。三个分项各占两分，成品达到的质量和交付数量分别统计。
- 任务完成率保持或提高。分母是每版冻结的全部试次，包含超限或缺失成品的题目。

这三项需要同时满足。来源跟踪覆盖常用 SDK 搭建路径。自行用坐标重新创建一个零件时，SDK 不再持有原放置实例的来源。
